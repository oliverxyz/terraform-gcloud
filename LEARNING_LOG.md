## Этап 0. Фундамент

### IAM и роли
1. **Минимальные права.** При подборе ролей проходи по каждому этапу плана, а не только по названиям сервисов: IAM, включение API, actAs и исключения в сетевых ролях легко пропустить.
2. **Проверяй точный ID роли в справочнике**, не угадывай по названию. Права IAM разнесены между `iam.*` и `resourcemanager.*`.
3. **Проверяй роль по всему жизненному циклу ресурса** (create → update → IAM → delete), а не только по созданию. Иначе `destroy` или изменения упадут с 403.
4. **Role ≠ permission.** Permission — отдельное действие (`iam.serviceAccounts.actAs`), role — набор permissions. Выдаются роли.
5. **Совпадение слова в названии ≠ нужный сервис.** `roles/apim.*` — не Service Usage.
6. **Если permission есть в нескольких ролях, выбирай самую узкую** (`resourcemanager.projectIamAdmin` вместо `iam.securityAdmin`).
7. **actAs:** чтобы запустить VM или узел GKE от имени сервисного аккаунта, нужна `roles/iam.serviceAccountUser` на этот аккаунт. Это защита от эскалации привилегий. **[прямой ответ]**
8. **State отражает реальность после частичного сбоя.** Неудачный `apply`/`destroy` не ломает state, повторный запуск продолжает.
9. **Если у аккаунта есть право менять IAM проекта, узкие роли не спасают при чужом доступе.** Главная защита — способ входа: impersonation без ключей.

### HCL и ресурсы Terraform
10. **Синтаксис коллекций HCL:** список — `[ ]`, map/объект — `{ }`. «Expected an attribute value» = парсер ждал `ключ = значение`. `toset()` принимает одну коллекцию, а не много аргументов.
11. **Направление IAM:** роль *на ресурс* (`google_service_account_iam_*`) и роль *аккаунту на проект* (`google_project_iam_*`) задаются разными ресурсами.
12. **`_binding` авторитетный:** перезаписывает список участников этой роли. По умолчанию используем `_member`.
13. **Область действия роли = ресурс, на чьей политике она висит.** На проекте — всё внутри, включая будущие ресурсы; на конкретном ресурсе — только он. **[прямой ответ]**
14. **Права проверяются цепочкой.** Если A может стать B, у A фактически есть все права B.
15. **Атрибут `id` ≠ email.** `id` — путь к ресурсу в API (`projects/.../serviceAccounts/...`), не формат участника IAM.
16. **Ссылка строится на ресурс-источник:** `<тип>.<имя>.<атрибут>` (B ссылается на A).
17. **Зависимость в графе создаёт ссылка.** `(known after apply)` показывает лишь, что провайдер не может вычислить значение заранее (`email` и `member` сервисного аккаунта он вычисляет до создания, `name` — нет).
18. **Аргумент ≠ атрибут.** Ссылка на свой аргумент возвращает то, что ты задал. Данные вроде `member` появляются в атрибутах.
19. **В IAM-ресурсе для конкретного ресурса два «адреса»:** *на что* (`service_account_id`, `project`, `bucket`) и *кому* (`member`).
20. **Три IAM-ресурса — разные аргументы:** `_policy` (`policy_data`), `_binding` (`role` + `members`), `_member` (`role` + `member`).
21. **`service_account_id` ждёт полный путь**, а не короткий ID. Берётся из атрибута `name` (или `id`) сервисного аккаунта. **[подсказка 3]**
22. **Bootstrap выполняется от твоего имени, основная конфигурация — через `impersonate_service_account`.** Нельзя выдавать себя за аккаунт, который этот же код ещё создаёт. **[прямой ответ]**
23. **Terraform авторизуется через ADC** (`gcloud auth application-default login`), а не через `gcloud auth login`.
24. **Потеря state:** Terraform перестаёт управлять ресурсами (повторное создание даст 409, `destroy` ничего не удалит). Восстановление — `import`; защита — remote state с версионированием.

### Бакет для state (шаг 0.3)
25. **Один регион для всего стенда** (`europe-southwest1`). «Ближайший» значит ближайший к ресурсам, а не к тебе; разные регионы — путаница и лишний межрегиональный трафик.
26. **IAM и ACL — две независимые системы доступа в GCS.** Uniform bucket-level access не замена IAM, а отключение ACL, чтобы IAM остался единственным механизмом.
27. **Откат state ≠ откат инфраструктуры.** Старая версия state восстанавливает «память» Terraform после порчи или потери, реальные ресурсы она не меняет.
28. **Бакет со state защищают от удаления**, а не облегчают удаление: `force_destroy` выключен.
29. **`prevent_destroy` и `force_destroy = false` — разные уровни защиты.** `prevent_destroy` — Terraform, ошибка на `plan` при любом удалении или пересоздании; пропадает, если удалить блок ресурса из кода. `force_destroy = false` — отказ API GCP на `apply`, и только для **непустого** бакета: пустой удалится.
30. **Сверяй `plan` с замыслом, а не только счётчик `N to add`.** Устаревший `plan` (запущенный до сохранения файла) может показывать не то, что в коде.
31. **У каждой конфигурации свой `prefix` в backend.** State лежит как `<prefix>/default.tfstate`; одинаковый prefix у двух конфигураций — они перезапишут state друг друга.
32. **В `backend` нельзя использовать переменные:** backend нужен уже на `init`, раньше, чем вычисляется остальная конфигурация. Обход — partial configuration (`-backend-config`).
33. **Bootstrap хранит state в бакете, который сам создал:** сначала `apply` с local state, потом `init -migrate-state`. При создании с нуля порядок повторяется.
34. **Смена неизменяемого аргумента у ресурса со state:** сначала увести state в безопасное место (local), потом пересоздавать ресурс, потом мигрировать state обратно. Новый бакет должен существовать до переключения backend.
35. **Ручные изменения через консоль — это drift.** Terraform находит их на refresh перед `plan` («Objects have changed outside of Terraform»). Работает, но лучше менять всё через код, иначе state и реальность расходятся.
36. **Блокировка state в GCS:** второй `apply` по умолчанию сразу падает с «Error acquiring the state lock», а не ждёт; ждать заставляет `-lock-timeout`. Блокировка — объект `.tflock` рядом со state.
37. **Восстановление state из версии:** `gcloud storage ls -a` показывает поколения объекта; нужное копируется поверх текущего, затем `plan` проверяет расхождения с реальностью.

## Этап 1. Сеть

38. **Имена API обманчивы.** `sqladmin` (не только `sql-component`), `storage` (не `storage-component`), `servicenetworking` (не `networkservices`), `artifactregistry` (Container Registry — устаревший предшественник). Сверяй API с разделом *Enable the API* в документации сервиса.
39. **`disable_on_destroy = false` для `google_project_service`.** Иначе `destroy` выключит API и может задеть ресурсы, которые от него зависят (включая bootstrap). Service Usage и Resource Manager через Terraform не трогаем — через них Terraform сам работает.
40. **VPC в custom mode.** Auto mode создаёт подсеть в каждом регионе с диапазонами Google; свои secondary ranges для подов и сервисов GKE (VPC-native) и контроль адресации даёт только custom mode. **[прямой ответ]**
41. **`plan -out` — бинарный файл с state, конфигурацией и значениями.** Относиться как к секрету, держать в `.gitignore`. Текст для чтения — `terraform plan -no-color > file` или `terraform show -no-color <план>`.
42. **`plan` не проверяет авторизацию полностью.** При пустом state читать из API нечего, поэтому ошибка в `impersonate_service_account` (нужен полный email, а не короткий ID) всплывёт только на `apply`.
43. **`depends_on` — явная зависимость там, где нет ссылки** (API → ресурс). На ресурс с `for_each` можно сослаться целиком или на конкретный экземпляр по ключу.
44. **GKE выдаёт каждому узлу целый блок из диапазона подов** (`/24` при `max_pods_per_node` = 110). Диапазон подов считается как «узлов × блок», а не «сколько подов нужно»: 2 узла → `/23`.
45. **CIDR-блок начинается с адреса, кратного своему размеру** (`/23` — с чётного третьего октета). План адресов: primary `192.168.0.0/28`, pods `192.168.2.0/23`, services `192.168.4.0/26`, Cloud SQL `192.168.6.0/24`.
46. **VM без внешнего IP по умолчанию не достаёт до API Google.** `private_ip_google_access` на подсети открывает путь к `*.googleapis.com` по внутренней сети, без NAT.
47. **Cloud NAT — только исходящий трафик** (узел/под начинает соединение, ответы возвращаются). Входящий доступ к приложению идёт через LoadBalancer/Ingress, а не через NAT. NAT нужен для интернета вне API Google: Docker Hub, внешние API, пакеты.
48. **GKE находит secondary-диапазоны по `range_name`**, а не по имени подсети: в кластере (`ip_allocation_policy`) указываются подсеть и имена диапазонов для подов и сервисов.
49. **Предусловия bootstrap — API, через которые работает сам Terraform** (`cloudresourcemanager`, `serviceusage`). Включаются вручную (`gcloud services enable`) или в bootstrap, а не тем же кодом. «API has not been used in project N» — проверь, что N — номер твоего проекта, и включи API.
50. **`(known after apply)` у аргумента, который ты собирался задать, — значит, ты его не задал.** Пропущенный `private_ip_google_access` дал бы `false` по умолчанию и `ImagePullBackOff` на приватных узлах. Переименование ресурса после `apply` = удаление + создание. **[прямой ответ]**
